# 第十八章 键的节奏与按钮激活

第十二章留的口子：Enter 落到焦点持有的按钮上，被按在「不激活」。当时的推迟有明确理由——瞬时按钮的全部反馈就是按压那一格像素，按下和抬起之间必须有一帧让按压被看见，而当时的运行循环一轮排空整个事件队列再重画一次，按下和抬起若同轮到达，按压帧结构性不存在。这个理由先把问题钉住，等的是节奏故事。本批讲完这个故事：一轮一键（作者 2026-10-12 拍板），KeyUp 消费者进场，Button 的键盘激活落地，B6 那条判例翻案。

## 节奏故事：为什么是轮次，不是重复也不是时钟

候选故事有三条。宿主自动重复（按住期间宿主重复发 KeyDown）最先出局：重复只管长按期间的状态刷新，可长按期间按压状态本来就在屏上（它是状态，每轮重画都在）——同轮闪帧是轮次问题，不是刷新问题，重复救不了。时钟节奏（核心按毫秒节拍分轮）也出局：它把保证推给宿主的泵速，核心自己拿不出结构性证据，嵌入式宿主泵得快就丢帧。

第三条是结构性的：一轮只消费一个键事件。`run_dirty` 和 `run_once` 的泵排空指针事件、遇键即停，剩下的键留给下一轮：

```cpp
while (host::try_poll_event(host, event)) {
    ++consumed;
    dispatch_event(root, event);
    if (std::holds_alternative<host::KeyDown>(event) ||
        std::holds_alternative<host::KeyUp>(event)) {
        break; // one key event per round: the rhythm rule above
    }
}
```

按下与抬起从此不可能同轮，中间至少隔着一次重画——按压帧的存在由泵的结构保证，不借宿主的重复行为，也不借时钟。这与「脏区永不欠覆盖」是同一种口味：保证长在结构里，不长在约定里。指针事件免费排空是同一判断的另一半：指针流是位置的采样，不是时间的节拍，拖拽的一串移动事件挤在同一轮里正是拖拽的自然形状。

代价照实说：连发键按轮串行，60Hz 一轮约 16ms 一键，打字无感，Tab 连按一轮走一步。事件队列满则拒新的既有规则照旧，泵得慢加上按得飞快才可能丢事件，这是明码的取舍。

## KeyUp 消费者

第十章给 KeyDown 立的投递规矩原样延伸：KeyUp 走同一条路，焦点持有者收，码点原样交。`Widget` 长出 `on_key_up`，默认空体是老立场（不跟键盘的控件诚实地什么都不做）。Tab 的抬起跟其他码点一样交给持有者自行解释——遍历语义住在按下上，抬起不该有第二个遍历。

## Button：压下与完成

激活语义四条。Enter 或 Space 压下（视觉翻暗、申报欠画），抬起完成（翻回、申报、回调开火）——瞬时按钮的意义就是先看见按压再看见效果。配对严格：按下的码记下，抬起的码对不上就当没听见，别人的按下回家不该引爆我的激活。重复的按下（宿主自动重复或第二个键）不改状态，第一按占住槽位直到它自己的抬起。指针与键盘双源各自记账，各自释放各自开火——按住指针再按 Enter 是要两次激活，就给两次；按压视觉是两源的或，谁还按着谁保持暗。

回调是裸函数加一个上下文词：`set_on_activate(void(*)(Button&, void*), void*)`。没有闭包、没有 `std::function`，词汇表保持裸指针——将来 Cinux 链接的 freestanding 纪律（核心零 STL 容器）在这里提前落了地。没接回调的按钮照样压照样画，抬起开火开进安静里，与空宿主表的同款姿态。

Checkbox 是刻意的对照，一行不改：它的翻转就是它的按压（按下调即翻、翻转自持自画），所以它吃按下不吃抬起。两种节奏并存是控件语义的分野，不是不一致。

## 判例实录

B6 的推迟判例翻案成节奏判例：Tab、Enter 按下、Enter 抬起、一个指针移动四事件入队，四轮各吃一键一移——第二轮后按压像素在屏上（(4,4) 暗）、计数为零，第三轮后翻回、计数为一，第四轮移动免费排空。同轮多键的老判例全部随轮次语义随迁：Tab×2 改两轮各一，复选框的 Tab、Enter、Space、陌生码四个键改四轮，判例七的三轮重排成六轮（Tab、Space、Tab、Enter 下、Enter 上、空转），提交次数跟着重算。

新的期望错一回，又是像素数学：6x6 的复选框盒只有 2x2、内芯是空矩形，勾与不勾在这个尺寸下像素同形，人家把帧框位当内芯位断言「未勾为亮」。改判据为帧框像素加状态断言，注释写明这个尺寸下标记判据退化、状态行才是这一轮的话。判例不信任何人的心算，包括刚写完实现的人。

红绿探针两根。节奏探针把两个泵的 break 注掉（同轮多键回归），红 23 处：四份判例文件里的轮次计数、按压帧像素、激活时序全倒。激活探针把 `on_key_up` 里的 `activate()` 注掉，精确红 7 处，全是激活计数。两根都复原再绿。

tidy 顺手逼出一件挂账的兑现：`run_widget_tests` 长过函数体量线，B4 起挂着的「widget_tests 拆文件，判例再多就分」的时机到了。控件域判例（Label、按钮激活、复选框抬起免疫）搬进新的 `control_tests.cpp`，树与框架（绘制序、命中、焦点、申报通道）留在 `widget_tests.cpp`。替身画笔两边各持一份——测试替身不共享文件，与第十五章手写字模资产不跨文件共享是同一个立场。

## 验收

六道一条命令：

```console
$ VISOR_CHECK_JOBS=4 scripts/checks/acceptance.sh
acceptance: all green
```

亲手看一次按压帧。判例七的场景手工搭一遍（亮底全屏、复选框在条带 0、按钮在尾条带），Tab 两下把焦点送到按钮，然后 Enter 按下抬起分两轮各跑一次 `run_dirty`——两轮之间屏上按钮内部是暗的，第二轮后翻回、激活计数从零到一。

红绿实验两个。第一个，把 `run_loop.hpp` 里两个泵的 `break` 注掉，重建跑测试，看轮次计数与按压帧判例红成片（实录 23 处），复原再绿。第二个，把 `button.cpp` 里 `on_key_up` 的 `activate()` 注掉，看激活计数判例红 7 处而按压视觉判例全绿——视觉与开火是两根神经，复原再绿。
