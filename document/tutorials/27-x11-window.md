# 第二十七章 X11 窗口宿主

X 线第二批，作者点名冒烟提前：先看见窗口，纯逻辑的提交策略退后。本批把宿主表三口第一次接到真显示上——`bindings/x11` 长出 `X11WindowHost`（开窗、影子帧、事件泵），配一个 demo 二进制（`examples/x11_window`），判例跑在 Xvfb 上，真窗口冒烟在 WSLg 上亲手走。

## 开窗与三口

`open(display_name, width, height, scale)` 是个工厂：XOpenDisplay 失败返回空 optional，开显示失败是答案不是事故。scale 是整数缩放（默认 1）：窗口按放大后的尺寸建，出手前每个画布像素放大成 scale 见方的块，OLED 尺寸的画布在桌面上才有可看的个头。倍数必须取整是有讲究的——非整数缩放会让某些行比别的行粗，而锐利的块状本来就是 1bpp 的审美；核心与影子都保持 1:1，缩放只碰窗和最后一展，小于 1 与开显示失败同一条线答空 optional。建窗选事件掩码（暴露、键盘两词、指针三词，刻意不含 Resize），登记 WM_DELETE_WINDOW 协议，映射，返回。宿主表照离屏宿主的模子填：三个静态跳板加 this 做 context。时钟是 steady_clock 的毫秒数，纪元自取，时长靠无符号减法的老规矩。

## 影子帧与提交

flush 的两口分工：先把区域画进影子帧（画布同款打包，宿主就是屏幕的记忆），再从影子展开成 32bpp 的字交给 XPutImage，展开时按 scale 把每个画布像素写成横竖各 scale 个字。涂画逐位走 pixel_bit_position 那套词汇（整字节快路径还在离屏宿主家里，第二个买家出现时再搬家）。展开出的每个字只有两值：亮字按视觉通道掩码按位或（不写死 0xFFFFFF，视觉给什么通道就点什么灯），暗字零。XImage 描述的是自家缓冲，字节序与掩码填本机实况，数据指针指到区域在窗里的落位（条带与部分区域不做整幅搬运），服务器照读。越界区域拒收计数，与离屏宿主同一条诚实拒绝线。

暴露重放是影子帧存在的意义：屏幕丢了的像素影子还有，一个 Expose 事件就把那块重新摆上窗，核心一笔不用重画。暴露矩形要先与画布求交再动缓冲——窗口管理器的尺寸提示是建议不是法律（真机上一拉伸就破功），拉伸后的暴露事件按新窗口尺寸来，不裁就往缓冲外写，堆当场被踩。第一版按收到的区域直送，合并坍缩那种提交策略等真窗口的数据回来再立批。

## 事件泵

poll 一次吐一个核心词，泵里的事比离屏多三样。ClientMessage 先查——窗口管理器的关门词不走事件掩码，XCheckTypedWindowEvent 单独捞它，对上 WM_DELETE_WINDOW 就置 close_requested，不是核心词。然后走掩码队列：Expose 重放后继续抽（它不是核心词），键盘词先过 XLookupString 解析 keysym 再进 B20 的翻译表（解析要连显示查键表，这正是翻译件当初把 keysym 解析划给 X 半边的原因），无名键丢弃继续，指针三词直译。运动坐标透传含负数，指针可以在窗左上方。缩放宿主还有第四样：指针词说的是窗坐标，核心说的是画布坐标，直译之前要把位置除回 scale（整除向下，负数照负），不然一次点击落点偏出 scale 倍——判例端到端按窗坐标塞词验回画布坐标。

## 判例与探针实录

判例的夹具自己拉 Xvfb：fork 加 execlp 起 ：99（虚拟屏 640x480，装得下缩放判例的放大窗），XOpenDisplay 轮询最多十五秒（xkbcomp 编译键表要几秒），析构时只杀自己拉的那个。判例十组（含拉伸后的超大暴露不越界——真机冒烟逮住后补的红——与缩放两组：3 倍读回差分逐块对、scale 0 答空）：表三口与时钟走动、全幅读回差分（XGetImage 逐像素对画布位）、奇 x 部分区域只动自己（邻位存活）、越界拒收计数、三词事件端到端、关门词、暴露重放（先 XClearWindow 验真擦掉、Expose 后验影子答话）。

缩放判例首跑红在差分上（读回两万处不齐，横着没拉伸竖着拉伸了），排到根不在展开循环，是移动赋值漏搬新成员 scale_——open 返回时一移动，缩放就退回默认 1，窗是大的、出手是 1:1 的。教训记下：类里进新成员，移动构造与移动赋值的点名清单要跟着过一遍，编译器不提醒这一手。

期望写错两回。区域提交把画布基址当区域首址传了（FlushRegion 的契约是 pixels 指向区域自己的首字节，偏移到区域顶行才对）。越界判例以为 submit_region 会答假（它只对空表答假，拒收记在宿主的流水上）。

送词的路踩了一夜坑：XSendEvent 在这台 Xorg 上被整个吞掉（带掩码与 NoEventMask 两条路都探过，Status 说送了没人收），判例的缝换成 XPutBackEvent 直接把词塞进宿主自己的队列，合成的键盘词还得带上 display 字段否则 XLookupString 摸空指针崩给你看。这两课都写进了判例注释。探针两根：暴露重放断掉，红 2400 处（60x40 亮区的全数像素，真机拉伸踩堆与判例复现退出 139 是同一条路的实录）；涂画改成只点不擦，红 10660 处（三组读回判例的全部期望暗像素，4076 加 792 加 5792 能对上数）。

## 验收

六道一条命令：

```console
$ VISOR_CHECK_JOBS=4 scripts/checks/acceptance.sh
acceptance: all green
```

亲手冒烟。demo 在 examples 里，构建后对着真显示跑（WSLg 下 DISPLAY=:0）：

```console
$ cmake --build build --target x11_window
$ DISPLAY=:0 ./build/examples/x11_window
```

demo 用 4 倍缩放，窗口落在 512x256，控件才有个可看的个头。窗口弹出后点按钮、拖滑块、Tab 走焦点，拉伸一下窗口（画布之外是黑边，预期行为），点窗口的 X 干净退出。

红绿实验两个。第一个，把 poll_one 里 Expose 分支的 put_region 注掉，看暴露重放判例红（实录 2400 处），复原再绿。第二个，把 paint_shadow 里清位那行改成照样式 `byte | mask`，看三组读回判例红（实录 10660 处），复原再绿。
