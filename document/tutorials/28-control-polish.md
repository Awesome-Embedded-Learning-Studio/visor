# 第二十八章：让黑白控件有清楚的层次

上一章把像素送进了真正的窗口，但 128×64 放大四倍的三个色块只是冒烟样本。按钮没有文字，复选框靠整块翻色说明状态，滑块的两像素手柄也很难辨认。本章在同一条 1bpp 管线上整理控件，并把窗口示例换成一页可交互的设置面板。

## 先看结果

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=g++
cmake --build build
DISPLAY=:0 ./build/examples/x11_window
```

新示例的逻辑画布是 480×320，宿主按两倍显示为 960×640。尺寸只属于这个桌面示例，核心没有改成依赖桌面分辨率。`examples/demo_font.hpp` 是本项目手绘的 5×7 点阵字母与数字，不读系统字体，不引入字体库；小写输入使用对应的大写字形。

面板包含设备名输入框、复选框、亮度滑块、纸白／夜黑单选组、输出方式下拉框，以及实心和描边按钮。鼠标可以直接操作；Tab 遍历焦点，滑块用左右键，单选组用上下键，下拉框用 Enter 打开、上下键选择、Enter 确认。Apply 与 Reset 是示例内的状态反馈，不提交到硬件。

没有显示服务时，也能让同一棵控件树输出预览：

```bash
./build/examples/x11_window --snapshot /tmp/visor-controls.pbm
```

PBM 的 1 表示黑，而画布的 `Color::On` 表示点亮，导出时逐字节用 `255 - byte` 反转极性。这个示例的宽度恰好整字节对齐，没有尾部填充位。

## 一个像素的边框，也需要内容空间

`base::inset` 收在 `base/helpers/rect_helper.hpp`，通用矩形运算继续属于 base。`ui/control_style.hpp` 则收拢控件轮廓的重复几何：

- `inset` 把矩形往内收，空间用完就给空矩形。
- `inset_corners` 给一像素描边的内缘减小圆角。
- `paint_outline` 先画前景轮廓，再画背景内面。

按钮的标签水平、垂直居中，文字两侧至少留两个像素。默认按钮仍为实心，`set_outlined(true)` 切到描边；按压时反色，但始终保留轮廓。复选框使用轮廓、实心选中面和背景色的勾；圆形单选标记与标签之间留出间隔，每行的高度为字体行高加六像素。滑块手柄改为七像素宽的空心轮廓，并补上键盘左右键。

输入框使用三像素内边距。文字、可见窗口的宽度预算和光标共用这一片内容区域，光标不会再与边框合成一条线。下拉框的箭头垂直居中，文字为右侧箭头预留空间，展开后的高亮行与外框之间也有空隙。

鼠标按下可聚焦的控件时，`InputRouter` 先转移键盘焦点，再投递按下事件，点击输入框后即可直接输入。焦点由 `Widget` 统一绘制，边界交替使用前景和背景像素。这样焦点落在实心按钮或空心输入框上都有可见标记，而不必让每种控件猜测边缘下方是什么颜色。

## 字画出了控件框，会发生什么

画布裁剪只保证不写出缓冲。一个长标签即使没有越过屏幕，也可能覆盖旁边的控件。更麻烦的是脏区只申报自身 bounds，框外的文字残影就可能永远没人擦。

`draw_text_clipped` 在原有 `draw_text` 旁边增加一项内容裁剪。它仍用 `TextLayout` 排字，因而字距、换行、偏移和整数缩放没有第二套规则。整个字形位于内容框内时直接调用 `draw_bitmap`；只有跨过边界的字形才把点阵展开为像素块，并逐块与内容框求交。负的字形偏移、上下越界和放大后的边缘都走同一条路径。

按钮、输入框、单选组与下拉框都使用这一入口。它不访问平台，不分配内存，也不修改控件状态，五行条带重放与整幅绘制保持一致。

同时修正了 `Label::set_text` 的一个缺口：旧文字和新文字测量出来一样大时，`set_bounds` 会认为几何没有变化；现在标签还会显式申报内容的欠画，等长替换也能刷新。

## 主题要经过每一种控件

颜色由两个角色组成：背景与前景。没有绑定主题的文本控件继续使用构造时给的 ink；绑定后，Label、输入框、单选组、下拉框与滑块都服从主题。纸白与夜黑通过给根节点调用 `set_theme` 切换，根面板也使用对应背景。

保留既有 `kLightTheme`、`kDarkTheme` 的位极性，桌面示例自行声明 `kPaper`、`kNight`，避免把宿主中“点亮”与人眼看到的纸白背景混为一谈。

## 验收

```bash
VISOR_CHECK_JOBS=4 scripts/checks/acceptance.sh
```

既有控件像素判例随新几何更新，新增两组边界判例：

- 同一组控件在两种相反极性下逐像素互补；每种状态的五行条带重放与整幅绘制一致；长文字不写出控件自己申报的 bounds。
- 带负偏移的字形放大两倍、跨过内容框四边时，内容框内与完整参考绘制一致，框外始终保持原背景。

窗口示例的源码与字模也纳入统一的格式、静态检查范围。最后亲手在窗口中试一次主题切换、下拉选择和长文本删除：测试能证明像素边界，视觉上的疏密仍要用眼睛判断。
