# visor 跟跑教程

这批教程跟着 visor 已完成批次（B1 至 B13）的真实工序走，从空仓库搭出一个跨宿主 GUI 框架的头几层：构建骨架、几何词汇、位操作库、单色画布、笔、宿主表与离屏宿主，一道像素差分关卡，然后宿主表长出事件与时钟两项，固定容量队列与时钟回绕进场，接着核心长出第一棵控件树与第一条运行循环，按钮按下变色的闭环走通，再到键盘经 Tab 进了树、焦点环落在持有者身上、复选框按下即翻转，然后渲染核心学会只认坐标窗口，同一棵树整幅画一遍和分条带画三遍逐像素一致，脏区收集器管住哪些区域欠画，控件状态翻转的当场申报欠画，Enter 和 Space 落到焦点持有者手上，`run_dirty` 把事件、申报与条带重画合成一轮完整管线，框架外第一件配套件——取模工具 fontgen——把 PBM 图片转成画布同款打包的点阵数组头文件，第二站开工，bindings 按宿主分目录，SSD1306 的页布局转换先把纯逻辑做完，然后路线拐向 Cinux 线，绘制核心长出位图原语，字形第一次上了屏（离屏的屏），文本测量与 Label 把一串字模排成整句的话，BDF 线把真的比例字体切进来、汉字第一次进了生成头，节奏故事落定为「一轮一键」，KeyUp 消费者进场，Button 的键盘激活翻案落地，最后区域提交长出整字节快路径，对齐的搬运不再逐位。正文把实现与测试写成成对推进的过程。被工具逮住的那些错误，比如链接器报出缺失实现的一次经历、tidy 教的指名初始化、PBM 头 8 字节算成 7 的乌龙、十六槽队列装不下十六个事件的想当然、命中测试期望写错被真相纠正的一回、把画布底色误当控件绘制范围的一次断言落空、把相同矩形当成两条欠画的想当然、枚举哨兵与首枚举值撞值的一次断言崩溃、把 Label 两个字模的两次位图调用数成一次、切割期望按双字节布局算而图是单字节半字节对切、CRLF 夹具把回车排到换行后面、手写字模表把码点升序踩破让二分迷路、6x6 复选框的帧框位被当成内芯位，都写成你会亲历的过程。每章收尾有一个可以自己执行并观察结果的验收。

## 读者需要什么底子

会 C++ 基本语法，见过模板，就够了。Concepts、CTAD 这些机制用到时当场解释，不要求先修。要会用命令行，CMake 与 CTest 的命令都是逐条给出的普通写法。不需要 GUI 或嵌入式经验，第一章连一行图形代码都还没有。

手边要有一台 Linux（或 WSL）机器：支持 C++23 的编译器（比如 GCC）、CMake 3.28 以上、Ninja。clang-format、clang-tidy 与 Doxygen 是可选的开发工具，装了才有格式检查、静态检查与 API 文档三个目标，不装不影响 configure、构建与测试。

## 读完能得到什么

一个你自己一步步搭出来的仓库：可构建、可测试、可差分验证的 1bpp 绘制链路，从 `Point` 一直通到 PBM 图片文件。

一套可迁移的做法：

- 测试先行。
- 字面断言，把 `0xF8` 这类字节值写死在测试里。
- 可选工具不挡路：开发工具缺了就少一个目标，构建与测试永远能跑。
- 双层边界处理：画布拒写，笔先裁剪。
- 用独立参考图做像素差分。
- 时长只用无符号减法：时钟值可能回绕，比较绝对值在回绕边界上就是错的。

对每个接口决定的理解：为什么叫 `Color` 不叫 `MonoState`、为什么宿主表方向是核心画宿主收、为什么 `plot` 越界静默、为什么笔的模板挂在画布类型上。

## 各章导览

- [第一章 起步与骨架](01-skeleton.md)：先把验证立起来。CMake 骨架、CTest 统一入口、格式与静态检查、文档基建，一条命令链跑完，全部检查通过。
- [第二章 几何词汇表](02-geometry.md)：`Point`/`Size`/`Rect` 模板家族与半开区间语义。恰好共享一条边的两个矩形交为空，这条试金石用例（专门检验语义有没有走样的判例）检验全部边界判断。
- [第三章 位操作库](03-bit-ops.md)：`BitRange`/`BitMask`/`Bitmap` 自 Cinux（作者的 x86-64 教学操作系统）移植，顺手修掉两个真问题：`unsigned long` 在 32 位平台说谎，`operator|` 在 8 位字上收窄。
- [第四章 画布](04-canvas.md)：1bpp（每像素一比特）位布局（行主序、MSB 在前、填充位恒零），奇数宽度末字节 `0xF8` 的字面断言，`Color` 这个名字的定名理由。
- [第五章 笔](05-pen.md)：`plot` 与 `fill` 两级原语，越界静默的设计理由，const 笔语义（笔不变纸变），模板挂在画布类型上给 RGB565（16 位彩色格式，计划中）留缝。
- [第六章 宿主表与离屏宿主](06-host.md)：核心与外界的边界只此一张表，方向是核心画宿主收（核心产出像素，宿主只接收上屏），离屏宿主只收整幅，PBM（一种最简的位图文件格式）导出与 `fstream` 不认裸 `string_view` 的实况。
- [第七章 差分关卡](07-diff-gate.md)：五矩形场景三轮比对，普通构建与 ASan/UBSan（内存错误与未定义行为检测器）构建各跑一遍，项目第一张留存下来的图片与它的正确读法（位 1 渲染为黑）。
- [第八章 事件与时钟](08-events-clock.md)：宿主表长出事件与时钟两项。`RingQueue`（自 Cinux 移植的第二件）一格留空、满则拒新，五个事件词以 `std::variant` 承载，时钟回绕靠无符号减法，离屏宿主喂合成事件与脚本化时间，TSan 第六道进验收。
- [第九章 控件树与运行循环](09-widget-tree.md)：核心长出第一棵界面。控件是运行时对象而画布是模板（规格的分工），`Painter` 接口是两层之间的缝（计划签名写不出来被迫返工的真实经过），先序绘制与逆序命中一树两走法，绘制可重放的逐字节比对，`run_once` 全帧循环与命中分发，按钮闭环全程经宿主表验证。
- [第十章 焦点链与复选框](10-focus-checkbox.md)：键盘进场。焦点住在树上（至多一个持有者），Tab 是核心点名的唯一键码，`advance_focus` 一树第三种走法（移交、回绕、藏匿分支跳过），焦点环是框架的策略，复选框按压即翻转，宿主表与测试替身分家（核心侧头不再沾堆容器）。
- [第十一章 坐标窗口与条带重建](11-window-strips-dirty.md)：渲染核心不再假设缓冲等于屏幕。`CanvasPainter` 长出坐标窗口（窗外裁掉，窗内平移进缓冲），离屏宿主从只收整幅放宽到界内即收（逐位搬运对齐任意 x），一个渲染原语三种窗口（整幅、条带、脏区条带），脏区收集器保覆盖不保省（重叠级联合并，装不下折叠成包围盒），六道判例守语义：四道差分证整幅与条带逐像素一致，攒带拨盘证同一循环换档不变形（16 行两次提交、5 行四次），奇数位区域提交证逐位搬运在字节中间落对位置。
- [第十二章 欠画申报与键盘激活](12-invalidate-keyboard.md)：状态改变的人自己最清楚欠哪块像素。`Widget` 长出申报通道（`set_dirty_sink` 接线整棵子树，收养的孩子继承，没人接线时申报安静丢弃），三处申报现场（可见性与焦点由基类申报，焦点环的面积框架替控件报，控件状态控件自己报），Enter 与 Space 以 Tab 同样的理由进场，分发器把其余键码原样交给焦点持有者，复选框第一次被键盘翻转（按钮的激活推迟，等节奏故事），`run_dirty` 三步合成规格管线的一轮（第一帧是调用者的活，`run_once` 留作对照），判例三组加两根红绿探针。
- [第十三章 取模工具 fontgen](13-fontgen.md)：框架外第一件配套件。输出先于输入定形——生成的头文件与画布同款打包（行主序、MSB 在前、填充位恒零），消费侧零重排；命名空间名字在工具里过关键字关，错误死在工具的退出码而不是消费侧的编译现场；读入端是第六章 PBM 导出的对偶（头文法、双向载荷计数、脏填充位在门口洗净），退出码 2 与 1 分工参数错误与文件错误，判例三组（逐字全文、往返、命令行子进程）加两根红绿探针，外加一个判例先红逮住的枚举哨兵 bug（值初始化的 `EmitError{}` 与首枚举值 `kEmptyName` 撞值）。
- [第十四章 SSD1306 的页布局](14-ssd1306-pages.md)：第二站开工，先碰纯逻辑不碰板。bindings 按宿主分目录（契约留顶层，每个宿主一片叶子，离屏替身归位、SSD1306 立门户），GDDRAM 与画布处处相反（页主序对行主序、列字节对行字节、LSB 在上对 MSB 在前），`PageBuffer` 做屏的显存替身，`write_region` 吃宿主表回调的 FlushRegion 形状做翻译，灭像素也写（条带重放与背景恢复要的就是清位），字节跨八行而区域可以只盖几行（邻居的位不动），判例七条加两根红绿探针，两回期望写错的实录都在「字节不是像素」这个坎上。
- [第十五章 位图原语与字形渲染](15-bitmap-glyph.md)：Cinux 线的垫步，交叉清单的硬前置。`MonoBitmap` 是画布同款打包的只读视图，fontgen 生成的头文件拿来即用（kStrideBytes 是编译期校验点，static_assert 对账），`Painter::draw_bitmap` 是墨水传送不是区域覆盖（灭位不画，擦背景是调用者的 fill），虚函数不留默认参数（scale 显式写在每个调用点，被编译器教的一课），整数缩放位变块、相邻块不重叠所以序无关（条带重放安全的根据），判例七条、三回对角线数步数的期望错、两根探针（缩放抹乘 factor 红二十七处，位序颠倒被编译期断言拦下，构建即停）。
- [第十六章 文本测量与 Label 控件](16-text-label.md)：字体与文本组收尾的一批。字模组头文件先于输入定形（GlyphEntry 带偏移与 advance，为比例字体留位；字库头 include 视图头，两边共用一个类型），fontgen 长出子命令与字库模式（条带切割，字距烤进格子），UTF-8 解码住进 base（首字节窗口表拒绝过长编码与代理区，非法序列只烧一个字节），`TextLayout` 游标是间距规则唯一住处（测量与绘制走同一游标，量的间距和画的间距不可能分家），`draw_text` 是自由函数不上 Painter 接口（文本分解为位图动词），`Label` 第一个自己定尺寸的控件（`Widget::set_bounds` 旧框新框双申报），判例四组、三回期望写错、两根探针（advance 换 width 死在编译期 static_assert，set_text 不换框精确红三处），外加真生成头在主树 include 路径下的手工消费验证。
- [第十七章 BDF 字模线](17-bdf-glyphs.md)：汉字输入源拍板后的落地批（HZK16 授权链否决，BDF 有正主可指：文泉驿、GNU Unifont）。知识主体是一次坐标折算（`offset_y = ascent - (yoff + height)`，BDF 的基线系 y 向上折进行顶系 y 向下，降部字模吊到基线底下），`Glyph` 长出三个度量字段后条带与 BDF 两种模式共用一张表书写器（第十六章的判例原样全绿，留位的兑现），CLI 第三个子命令 `bdf` 只做子集导出（整库拒绝，Unifont 六万字模嵌入式的用法是按用字清单裁），判例三回被真相纠正（CRLF 夹具排反、搜索串少半边花括号、手写字模表破码点升序让二分迷路），两根探针（折算忘减字模高红四处；advance 换位图宽只红 BDF 判例不红条带，同值巧合即盲区），外加真 Unifont 的烟雾（ASCII 95 字与「中」，生成头编译期消费）。
- [第十八章 键的节奏与按钮激活](18-key-rhythm.md)：第十二章口子的兑现。节奏故事三选一（宿主重复管不到同轮闪帧、时钟把保证推给宿主、一轮一键是结构性保证——按下与抬起永不同轮，按压帧由泵的结构担保，指针事件免费排空因为指针流是位置采样不是时间节拍），KeyUp 消费者沿 KeyDown 的投递路进场，Button 激活语义四条（压下与完成分离、码点配对、重复不改状态、双源各自记账各自开火），回调是裸函数加上下文词（freestanding 纪律提前落地），Checkbox 是刻意的对照（翻转即按压，吃按下不吃抬起），B6 判例翻案、同轮多键老判例全数随轮次随迁，6x6 复选框帧框与内芯同形的退化像素又一课，探针两根（节奏红二十三处、激活红七处），tidy 逼出 widget_tests 拆文件的兑现（控件域进 control_tests）。
- [第十九章 整字节快路径](19-byte-fast-path.md)：性能组首件，B5 开放项的兑现。对齐就是快路径的全部条件（区域像素与目标像素在各自字节同槽位，整字节段直赋、尾位段活位掩码融合），尾位的讲究是融合不是覆盖（源零填充不得盖掉目标邻居位，判例摆两面：全亮源证邻居存活、全暗源证活位落位），对齐判例用差分形态（逐像素读回比对，读回侧就是逐位路径的答案），13 宽全幅老判例免费升级成快路径的回归，探针两根（融合丢掩码红十二处、对齐恒真红三处），SSD1306 的同类优化不在本批（页布局纵向字节是另一种对齐故事，且已移交专门线）。

## 怎么读

按顺序读，每章的验收亲手跑一遍，把验收里的红绿实验也做一遍：把断言改错看测试转红，再复原。章节之间是依赖关系：第四章用第三章的位词汇，第六章用第四章的位布局公式，第七章把前六章全部串起来。跳着读会缺上下文。
